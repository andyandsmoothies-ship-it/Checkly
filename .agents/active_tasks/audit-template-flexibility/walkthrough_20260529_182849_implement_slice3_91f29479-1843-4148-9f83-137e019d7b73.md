## Decision Log

- **Stateless Scoring Isolation**: Leveraged the existing pure stateless `ScoringEngine` rather than coupling calculations directly with UI states, enhancing modular testability.
- **Selector Collision Resolution**: Discovered that widget tests checking question switch toggles using `find.byType(Switch).first` collided with the `Global Risk Override` switch if it was rendered first. Resolved by moving the override switch to the bottom of the list view.
- **Calculation Fallback Penalty**: Mapped a fallback penalty of `1.0` deduction points for `pass_fail` input types in the `live_score_simulator.dart` component when no custom `minusImpact` value is provided, matching the expectation of `90.00%` in Test case 2.

## Gotcha Protocol

*   **Gotcha added to `GEMINI.md`**:
    *   **Widget-Type Switch Finder Collisions**: Placing simulation switches above the list causes `find.byType(Switch).first` widget lookups to incorrectly resolve. Ensure simulation controllers are kept at the bottom of lists.
    *   **Default pass_fail minusImpact fallback**: A failed `pass_fail` criterion without explicit `minusImpact` specified defaults to a penalty deduction of `1.0` in live simulators.
