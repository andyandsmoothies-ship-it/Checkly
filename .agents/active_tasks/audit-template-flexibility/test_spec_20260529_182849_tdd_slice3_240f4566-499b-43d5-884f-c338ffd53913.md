## Test Suite Design & Scenarios

The suite includes 8 distinct widget and responsive layout assertions covering:

1. **Initial Score State (All Passing)**: Verify that when all active criteria in the sections are passing (e.g. checkbox selected or pass_fail checked), the simulator computes a score of `100.00%`.
2. **Decreased Score (One Failed Criterion)**: Verify that toggling a `pass_fail` criterion to failing drops the overall score percentage accordingly (e.g. from `100.00%` to `90.00%` when a weighted item is unchecked).
3. **isRisk Assertion (Risk Badge Alert)**: Verify that when a criterion with `isRisk = true` fails, the score is forced to `0.00%` immediately and a red hazard/risk alert badge becomes visible on the screen.
4. **Survey Mode Bypasses**: Verify that when the scoring mode is set to `'survey'`, the simulator skips numeric scoring calculations and displays `Survey — no score` instead.
5. **Mixed Scoring Suppression**: Verify that when a measurable criterion (e.g., `pass_fail`) has `pointsWeight <= 0`, the purity gate fails. The simulator must hide the numeric score percentage and show `Mixed — score will be NULL` instead (matching backend BOD behavior).
6. **Global Risk Toggle Simulation**: Verify that checking the "Simulate global risk failure" switch forces the entire session score to `0.00%` immediately regardless of individual question status.
7. **Responsive Desktop Mode**: Verify that when viewport width >= 800px, a 3-column layout is rendered (containing both `TemplateLinterPanel` and `LiveScoreSimulator` in a Row alongside the tree editor).
8. **Responsive Mobile Mode**: Verify that when viewport width < 800px, the screen renders a `TabBar` containing 3 explicit tabs (`Design`, `Issues`, and `Simulator`) inside a `TabBarView`.

## Technical Instructions for the Builder

To make the tests pass, you must implement:

1. **Scoring logic extraction**: Expose the calculation logic of `ScoringEngine` (located in `lib/features/audit/services/` or `lib/_shared/services/`) as a reusable or pure stateless service (`scoring_calculator.dart` or similar) so it can be cleanly imported from the template builder domain.
2. **`LiveScoreSimulator`**: Implement the widget in `lib/features/templates/pages/widgets/live_score_simulator.dart` to:
   - Accept the sections tree (`sections`), current `scoringMode`, and `progressiveRepeat` configuration.
   - Render a list of criteria toggles (Checkboxes for `pass_fail`, text fields or numeric fields) to let the user simulate real-time auditor answers.
   - Compute and display the live score percentage, showing appropriate alerts for risk flags, survey mode, or mixed scoring.
   - Cancel any debounce timers or animation tickers in `dispose()` to prevent memory/test leaks.
3. **Responsive layout dispatcher**: Update `lib/features/templates/pages/template_builder_page.dart` to use a `LayoutBuilder` that selects the Row layout for width >= 800 and the TabBar layout for width < 800.

## Decision Log

- **Stateless Extraction**: We decided to extract the scoring calculation logic as a pure function / stateless service to prevent coupling between the template design module and the audit module.
- **Responsive Layout**: We rejected separate web/mobile route structures. We instead leverage a unified `LayoutBuilder` for visual consistency across device profiles.
- **Reduced Motion**: Bouncy list indicators and animated progress bars must respect user reduced motion configurations.

---
