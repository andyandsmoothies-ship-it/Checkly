# Task: Store Manager (SM3) 403 on Finalize
Workflow: /diagnose | Track: A

## Input Lineage
- **Source Input**: Log provided by user showing a `403` on `PUT /api/submissions/{id}/finalize` for user `sm3` (Store Manager).

## Hypotheses
1. The `sm3` user is NOT the original `AuditorId` of the submission (perhaps someone else started it), and `ResourceAccessGuard.CanDelegateAsync` rejects Store Managers (unlike Area Managers or Admins).
2. The user `sm3` *is* the original `AuditorId`, but there is another validation gate in `FinalizeSubmission.cs` or `SubmissionEndpoints.cs` that returns 403.
3. The previous fix (removing `.RequireCapability()`) failed to deploy or compile, meaning the route-level guard is still active and `sm3` lacks `submissions:create`.
