## What the Builder (Forge) Must Do

### Fix 1: `lib/_shared/widgets/permission_guard.dart`
Add `showAsDisabled` (bool, default false) and `disabledTooltip` (String?) parameters.

When `showAsDisabled=true` AND capability is absent:
- Render the `child` inside an `IgnorePointer(ignoring: true, child: Opacity(opacity: 0.5, child: child))`
- If `disabledTooltip != null`, wrap that in `Tooltip(message: disabledTooltip, ...)`
- Do NOT show the `fallback` widget

When `showAsDisabled=false` AND capability is absent (default):
- Existing behavior: render `fallback ?? SizedBox.shrink()`

## Constraints & Gotchas for Builder
- `PermissionGuard` is a `StatelessWidget` — it uses `ValueListenableBuilder` internally. The `showAsDisabled` rendering must stay inside the `builder` callback so it reacts to capability changes reactively.
- Do NOT stub `@protected` members on mocks (mocktail rule).
- `PermissionGuard` is registered via `GetIt` using `_di<AuthManager>()`. The mock tests use `GetIt.I.registerSingleton<AuthManager>` — the fix must not change how `AuthManager` is resolved from DI.
- `AdminAuditManager` uses `Future.wait([...])` and indexes results by position. The capability string change at index `[2]` is the ONLY required change in that file.
