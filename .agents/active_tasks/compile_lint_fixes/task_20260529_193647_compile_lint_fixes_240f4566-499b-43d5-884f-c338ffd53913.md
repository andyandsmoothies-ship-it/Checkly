## Internal Thoughts

### Initial Hypothesis
- **H1 (C# MSBuild)**: The compilation errors in `CheckAuditor` are caused by MSBuild recursively including and compiling unrelated C# scripts inside nested directories (`snapshot_refresher` and `DbDebug`).
- **H2 (C# dbquery nullability)**: The warning on parameter binding in `dbquery` is caused by `Guid?` conversion to non-nullable `object` parameters under modern C# `<Nullable>enable</Nullable>`.
- **H3 (Dart Lints)**: The Dart warnings are simple unused import and variable statements, and non-optimized nullable container-if checking in `bod_score_trend.dart`.

### Evidence Gathered
- Run `dotnet build` in `.agents/tmp/` -> Failed with 18 CS0260/CS8802/CS0579 errors.
- Confirmed that `snapshot_refresher` and `DbDebug` are child folders under `.agents/tmp/`.
- Confirmed `dbquery/Program.cs#L178` passes `(object)linkedAssignmentId ?? DBNull.Value` which causes a nullable conversion warning since Npgsql parameters expect `object`.
- View `checklist_calculator.dart` L61 -> Variable `sectionDeductions` is accumulated but never used.
- View test files -> Unused imports found (`dart:async`, `lint_result.dart`, `dart_template_linter.dart`).
- View `bod_score_trend.dart` L110 -> Collection-if uses `trajectoryChip` without null assert check.

### Root Cause Identified
- **C# MSBuild**: MSBuild default wildcard `<Compile Include="**\*.cs" />` behavior includes all child directory source files, causing duplicate `Program` class definitions and multiple entry points in one project.
- **C# nullability**: Casting nullable type `Guid?` directly to `object` in parameter assignment can lead to null conversions.
- **Dart**: Standard linter compliance details (unused items, collection-if type constraints).

### Fix Strategy
- Add explicit `<Compile Remove="..." />` declarations to `CheckAuditor.csproj`.
- Cast parameter binding in `dbquery/Program.cs` explicitly with ternary logic checking `.HasValue`.
- Prune unused variable and imports.
- Use `!` null assertion on `trajectoryChip` in `bod_score_trend.dart`.

## Falsifiable Hypotheses
1. *If MSBuild recursive compilation is the cause*, then adding `<Compile Remove="snapshot_refresher\**\*.cs" />` to `CheckAuditor.csproj` will compile `CheckAuditor` successfully with 0 errors. (Proven)
2. *If parameter nullability in dbquery is the cause*, then ternary check `linkedAssignmentId.HasValue ? (object)linkedAssignmentId.Value : DBNull.Value` will resolve the CS8600/CS8604 warning. (Proven)
3. *If unused imports/variables are the cause*, then deleting them will clear Dart linter warning outputs without altering program behavior. (Proven)
