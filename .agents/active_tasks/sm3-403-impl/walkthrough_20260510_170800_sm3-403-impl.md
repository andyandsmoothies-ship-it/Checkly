# Walkthrough: SM3 403 Finalize Fix

## Objective
Implement the fixes defined in `docs/diagnostics/failure_report_20260510_164800_sm3-403.md` to resolve the `403 Forbidden` error when a Store Manager attempts to finalize a Scheduled audit.

## Work Performed

### 1. Data Integrity Fix: `UpdateSubmission.cs`
- **Issue**: When an Admin created a Scheduled audit without a specific `AssignToAuditorId`, the system incorrectly defaulted `AuditorId` to the Admin's ID. When a Store Manager tapped "Start" to transition the status from `scheduled` to `draft`, the `UpdateSubmission` endpoint had a logic guard: `if (!submission.AuditorId.HasValue)`. Since the Admin's ID was already set, the Store Manager was prevented from officially claiming ownership in the database.
- **Implementation**: I removed the `HasValue` condition. The system now unconditionally applies `submission.AuditorId = callerId;` whenever an audit is started. This ensures perfect accountability: the person walking the floor and tapping "Start" is strictly recorded as the auditor.

### 2. Authorization Fix: `ResourceAccessGuard.cs`
- **Issue**: For existing drafts on Store Managers' devices that already suffered from the bug above, they were locked out. `FinalizeSubmission.cs` delegates authorization to `ResourceAccessGuard.CanDelegateAsync` if the submitting user's ID does not match the database `AuditorId`. The previous implementation of `CanDelegateAsync` outright rejected the `store_manager` role.
- **Implementation**: I extended `CanDelegateAsync` to permit the `store_manager` role to delegate/finalize resources, *provided* the resource strictly belongs to their assigned store (via `IsUserStoreAsync`). This safely unblocks in-flight submissions and gives Store Managers the logical right to assign/manage audits strictly within their own locations.

## Decision Log
- **Architectural Shift**: Transitioning the finalization workflow to allow Store Managers to act on scheduled drafts effectively elevates their role to match Area Managers within their specific retail boundary. This prevents blocking retail execution when a scheduled user is unavailable.
- **Why UpdateSubmission.cs vs Database Migration**: Altering `UpdateSubmission` corrects the root workflow moving forward, rather than manually hacking existing DB rows.
