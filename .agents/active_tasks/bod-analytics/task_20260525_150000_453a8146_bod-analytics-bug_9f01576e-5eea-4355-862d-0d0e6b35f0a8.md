# Task: Flutter setState() / markNeedsBuild() Called During Build in BOD Analytics Sheets

Workflow: /diagnose | Track: B1

## Input Lineage
- **Source Input**: c:\Users\HP\Documents\GitHub\Checkly\lib\features\analytics\manager\bod_analytics_manager.dart

## Diagnostic Reasoning
### 1. Initial Hypothesis
When the user clicks a card in the Boardroom (BOD) Analytics view, it opens a detail sheet (e.g., `BodStoreDetailSheet`, `BodCategoryDetailSheet`, or `BodAuditorDetailSheet`). In `initState()`, the sheet synchronously triggers a load operation on the shared `BodAnalyticsManager` ChangeNotifier. The load method immediately changes state (e.g., setting `_isStoreDetailLoading = true`) and synchronously calls `notifyListeners()`. Since the sheet or its parent is listening to this manager via `ListenableBuilder` or `AnimatedBuilder` that is currently in the middle of being built or layout, the synchronous `notifyListeners()` triggers `markNeedsBuild()` on the builder, violating Flutter's constraint that widgets cannot be marked dirty during the build phase.

### 2. Evidence Gathered
- Stack trace / log provided:
  ```text
  FlutterError (setState() or markNeedsBuild() called during build.
  The widget on which setState() or markNeedsBuild() was called was: ListenableBuilder
  The widget which was currently being built when the offending call was made was: NotificationListener<DraggableScrollableNotification>
  ```
- File inspection:
  - `bod_store_detail_sheet.dart` at line 28:
    ```dart
    @override
    void initState() {
      super.initState();
      widget.manager.loadStoreDetail(widget.storeId);
    }
    ```
  - `bod_analytics_manager.dart` at line 266:
    ```dart
    Future<void> loadStoreDetail(String storeId) async {
      if (_isStoreDetailLoading) return;
      _isStoreDetailLoading = true;
      _error = null;
      notifyListeners(); // <-- Synchronous notify during build/initState
    ```
  - `bod_category_detail_sheet.dart` and `bod_auditor_detail_sheet.dart` also trigger their respective load functions inside `initState()` without an asynchronous dispatch wrapper.

### 3. Root Cause Identified
The root cause is the synchronous invocation of `notifyListeners()` from the `initState()` lifecycle callback of the bottom sheets. When a widget's state is initialized, it is inside the framework's build/layout pipeline. Modifying a ChangeNotifier state and immediately notifying listeners causes active listening builders to call `setState`/`markNeedsBuild`, which throws a `FlutterError`.

### 4. Fix Strategy
To resolve this, we must ensure that the initial state updates and listener notifications from the load methods inside `initState()` are scheduled to run in the next microtask or after the current build frame completes. We can wrap the load trigger inside the bottom sheets' `initState` in a post-frame callback using `WidgetsBinding.instance.addPostFrameCallback((_) { ... })`. This matches the successful pattern already used in `bod_analytics_page.dart` (line 32).
