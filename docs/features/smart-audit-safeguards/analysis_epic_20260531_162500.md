## Executive Summary

The **Smart Audit Source Safeguards** Epic secures the offline audit execution loop against integrity fraud and enhances the auditor experience. We introduce two components:
1. **Bimodal Geofencing Constraints**: Templates define strict or lax GPS radius checks. Under strict geofencing, out-of-range submissions are blocked entirely. Under lax geofencing, auditors are warned but can bypass the boundary. All lax bypass distance deviations and bypass flags are logged offline first, synced, and persistently recorded in PostgreSQL.
2. **Debounced Auditor HUD**: A smooth real-time HUD scoring panel displays a live-calculating compliance score during audit execution, debounced at 200ms to eliminate layout stutter.

## Decision Matrix

### Shape A: Client-Side Enforcement Only
* **Description**: Geofencing validations are evaluated on the device using local coordinate calculations. Violations are blocked/warned entirely on the client, without persistent database columns or sync payloads.
* **Pros**: Simple, zero database changes on server or SQLite.
* **Cons**: Fails to provide operational audits. Boardroom/SRE cannot identify bypass fraud, bypass trends, or regional compliance patterns.
* **Impact**: Low operational leverage.

### Shape B: Bimodal Client-First Validation with Persistent Telemetry Sync (Selected)
* **Description**: Sync schemas on both .NET and Drift SQLite are updated. Mobile clients evaluate boundaries offline and cache coordinates, distance deviation, and bypass markers. The Outbox queue flushes telemetry data synchronously to the Postgres backend on reconnect.
* **Pros**: Bulletproof operational integrity; full executive audit reports; zero-friction offline support.
* **Cons**: Requires migration steps on both .NET Postgres and Flutter Drift.
* **Impact**: Maximum compliance visibility.

## Risk Assessment

### 1. Concurrency Sync Issues
* **Risk**: High latency syncing of pending outbox queue overwrites newer telemetry.
* **Mitigation**: GPS coordinates, bypass flags, and calculations are calculated and frozen in SQLite `PendingSubmissions` at the exact millisecond the auditor taps "Submit", shielding it from outbox sync-delay drift.

### 2. Device Battery Drain & Location warming
* **Risk**: Constant GPS polling during audit execution drains device battery.
* **Mitigation**: Fetch coordinate updates only when opening the submission checkout sheets, rather than continuously polling in the background.

## System Context

### 1. Offline & Sync Loop
- Local SQLite database `CachedTemplates` stores `geofenceMode` (`none`/`lax`/`strict`) and `geofenceRadiusMeters` (`int`).
- `CachedSubmissions` and `PendingSubmissions` capture coordinate fields (`gpsLat`, `gpsLng`), `isGeofenceBypassed` (`bool`), and `distanceMetersOff` (`int`).

## Lifecycle Context

### 1. Edge & Error States
- **GPS Signal Timeout**: If coordinates are unavailable, strict mode blocks submission. Lax mode permits bypass, setting `isGeofenceBypassed = true`, and logs GPS timeout context.
- **Save Drafts**: Draft states are saved locally without geofence validation. Validation triggers exclusively when the status transitions to `completed`.

### 2. Rollback Plan
If telemetry sync fails, default geofence configuration to `none` (fallback compatibility), allowing submissions to proceed smoothly.
