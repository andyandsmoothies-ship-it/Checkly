## The Accumulation Weighted Math
Weighted Accumulation mirrors Weighted Penalty but in the opposite direction:
- For each section: ratio = sectionEarned / sectionPossible
- Weighted score = Σ(ratio × section.weight / totalWeight) × 100

This is identical to PenaltyCalculator but without the "deduction" step — sections earn forward, not backward.

## Executive Summary

Two gaps exist in the current scoring system:

1. **Accumulation has no weighted mode.** The `isWeighted` toggle is silently disabled for `scoreDirection == 'up'` in the Template Builder UI, and the backend dispatch matrix routes all Accumulation submissions to a single unweighted calculator — ignoring the `isWeighted` flag entirely.

2. **Accumulation (Unweighted) shows points as the primary UI display instead of percentage.** In `ScoreFormatter`, the accumulation branch returns `'X / Y pts'` as primary, while the other 3 scoring modes all show percentage first. This inconsistency creates a confusing side-by-side comparison for users.

The fix is a **Calculator Dispatch Extension** (Strategy Pattern expansion):
- Add a `WeightedAccumulationCalculator` (new file) that mirrors `PenaltyCalculator`'s weighted section math but earns forward.
- Split the single `"up"` dispatch arm into `"up" + weighted` and `"up" + unweighted`.
- Unlock the `isWeighted` toggle in the Template Builder for Accumulation mode.
- Fix `ScoreFormatter` to show percentage first for all 4 modes.

## Risk Assessment

### Risk 1: ScoringInput Missing `isWeighted` for Accumulation (HIGH)
- `scoring_input_mapper.dart` line 134 maps `scoreDirection == 'up'` → `ScoringMode.accumulation` but does NOT store `isWeighted` on the ScoringInput model.
- The engine dispatch at line 97 receives only `ScoringMode.accumulation` — no weighted flag.
- **Mitigation**: Verify `ScoringInput` has `isWeighted` field. If not, add it. Map it from `scoringLogicConfig['isWeighted']` in the input mapper.

### Risk 2: Template Builder Silently Resets isWeighted to false for 'up' (MEDIUM)
- `template_builder_page.dart` line 73: `_scoreDirection == 'up' ? 'accumulation' : ...` — this only affects the scoringMode string, not `_isWeighted` directly.
- BUT `metadata_form_card.dart` line 116: `value: (scoreDirection == 'none' || scoreDirection == 'up') ? false : isWeighted` — the toggle DISPLAYS false even if `_isWeighted` is true.
- When user saves, the JSON will carry `isWeighted: _isWeighted` — the actual value.
- **Mitigation**: Remove the `|| scoreDirection == 'up'` short-circuit. The SwitchListTile must reflect and update `_isWeighted` freely for 'up' direction.

### Risk 3: Template Wizard Hardcodes isWeighted = false for Accumulation (HIGH)
- `template_wizard_page_logic.dart` line 84: `isWeighted: _scoringMode == 'penalty'` — only Penalty gets `isWeighted: true`. Accumulation always gets `false`.
- **Mitigation**: Replace with `isWeighted: _isWeighted` (the actual user-controlled flag).

### Risk 4: Backend Dispatch Ignores isWeighted for 'up' (HIGH)
- `ScoringVerifier.cs` line 76: `"up" => ScoringCalculators.VerifyAccumulation(...)` — no isWeighted check.
- **Mitigation**: Split to `"up" when isWeighted => VerifyAccumulationWeighted(...)` and `"up" => VerifyAccumulation(...)`.

### Risk 5: ScoreFormatter Accumulation Branch is Inconsistent (MEDIUM)
- Line 16-20: Shows `'X / Y pts'` as primary for accumulation regardless of isWeighted.
- **Mitigation**: Rewrite the accumulation branch to show `'%'` as primary, `'X / Y raw pts'` as secondary (same pattern as Penalty weighted).
