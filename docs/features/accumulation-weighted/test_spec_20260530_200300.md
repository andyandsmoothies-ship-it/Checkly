# Test Specification: Weighted Accumulation scoring logic (Slice 2)
**Epic**: Accumulation Weighted Scoring Engine (`ACCUM-WEIGHTED`)  
**Session Date**: 2026-05-30  
**Conversation ID**: `f2960312-360f-408a-92a4-699802f89d10`

## 1. Scope of Tests
These backend C# integration unit tests cover the `ScoringVerifier` public API calculation logic for the new weighted accumulation scoring mode. All tests are isolated from external dependencies and run purely in-memory using static fixtures.

---

## 2. Test Cases (TC-01 through TC-07)

### TC-01: Happy Path — Two sections, weighted score calculated correctly
* **Description**: Verifies that when two sections are defined with explicit weights, the earned percentages are weighted and aggregated.
* **Given**:
  * Section A (Weight = 60.0), earns 8.0 out of 10.0 max points.
  * Section B (Weight = 40.0), earns 5.0 out of 10.0 max points.
* **When**: Verifier is executed with `scoreDirection: "up", isWeighted: true`.
* **Then**:
  * The final total score must be exactly `68.0%` (i.e. `((8/10 * 60) + (5/10 * 40)) / (60 + 40) * 100`).
  * The result's `IsWeighted` flag must be `true`.

### TC-02: CCP Triggered — Section score zeroed but weight still counts in total weight
* **Description**: Verifies that when a CCP is triggered inside a section, the section ratio becomes 0, but the weight stays in the denominator.
* **Given**:
  * Section A (Weight = 60.0), earns 8.0 out of 10.0 points but triggers a CCP fault.
  * Section B (Weight = 40.0), earns 5.0 out of 10.0 points.
* **When**: Verifier is executed.
* **Then**:
  * The final total score must be exactly `20.0%` (i.e. `((0.0 * 60) + (5/10 * 40)) / (60 + 40) * 100`).

### TC-03: Perfect Score — Earns 100%
* **Description**: Verifies that when all answers are fully conformant, the final score scales perfectly to 100.0%.
* **Given**:
  * Section A (Weight = 70.0), earns 10.0 out of 10.0 points.
  * Section B (Weight = 30.0), earns 10.0 out of 10.0 points.
* **When**: Verifier is executed.
* **Then**:
  * The final total score must be exactly `100.0%`.

### TC-05: Regression — Unweighted Accumulation Unchanged
* **Description**: Verifies that when `isWeighted` is false, it uses traditional unweighted accumulation.
* **Given**:
  * Section A (Weight = 60.0), earns 8.0 out of 10.0 max points.
  * Section B (Weight = 40.0), earns 5.0 out of 10.0 max points.
* **When**: Verifier is executed with `isWeighted: false`.
* **Then**:
  * The final total score must be exactly `65.0%` (flat accumulation).
  * `IsWeighted` on the result must be `null` (matching existing unweighted stamps).
  * Flat fields `RawEarned` and `RawMax` must be `13` and `20`.

### TC-05b: Zero Weights Fallback — Falls back to unweighted calculation
* **Description**: Verifies that if all section weights are null or zero, the system falls back to unweighted calculation.
* **Given**:
  * Section A (Weight = null), earns 8.0 out of 10.0 points.
  * Section B (Weight = 0.0), earns 5.0 out of 10.0 points.
* **When**: Verifier is executed with `isWeighted: true`.
* **Then**:
  * The final total score must be `65.0%`.
  * `IsWeighted` must be stamped as `false` to explicitly indicate a fallback has occurred.

### TC-06: Tolerance Boundary — Client Within ±0.01 Is Valid
* **Description**: Verifies that the client score within ±0.01 threshold is valid.
* **Given**:
  * Fixture equals TC-01 (weighted score = 68.0). Client score = 68.005.
* **Then**:
  * `IsValid` must be `true`.

### TC-07: Tolerance Boundary — Client Exceeds ±0.01 Is Invalid
* **Description**: Verifies that a client score exceeding the threshold fails verification.
* **Given**:
  * Fixture equals TC-01 (weighted score = 68.0). Client score = 68.02.
* **Then**:
  * `IsValid` must be `false`.
  * The server score must return `68.0%`.
