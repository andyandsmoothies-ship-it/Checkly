## 1. Scope of Tests
These unit tests cover both the `ScoringEngine` calculation logic for the new weighted accumulation mode and the `ScoringInputMapper` mapping of the JSON configuration to the appropriate `ScoringInput` fields. All tests are isolated from external dependencies and run purely in-memory.

---

## 2. Test Cases (TC-01 through TC-07)

### TC-01: Happy Path — Two sections, weighted score calculated correctly
* **Description**: Verifies that when two sections are defined with explicit section weights (e.g., 60 and 40), the earned percentages are weighted and aggregated.
* **Given**:
  * Section A (Weight = 60.0), earns 8.0 out of 10.0 max points.
  * Section B (Weight = 40.0), earns 5.0 out of 10.0 max points.
* **When**: ScoringEngine.calculate() is run.
* **Then**:
  * The final total score must be exactly `68.0%` (i.e. `((8/10 * 60) + (5/10 * 40)) / (60 + 40) * 100`).
  * Section scores themselves must retain correct earned and max points.

### TC-02: Perfect Score — Earns 100%
* **Description**: Verifies that when all answers are fully conformant, the final score scales perfectly to 100.0%.
* **Given**:
  * Section A (Weight = 70.0), earns 10.0 out of 10.0 max points.
  * Section B (Weight = 30.0), earns 10.0 out of 10.0 max points.
* **When**: ScoringEngine.calculate() is run.
* **Then**:
  * The final total score must be exactly `100.0%`.

### TC-03: CCP Triggered — Section score zeroed but weight still counts in total weight
* **Description**: Verifies the SRE edge case for Critical Control Point (CCP) failures. When a CCP fails inside a section, the section score is zeroed out, but the section's weight still counts in the denominator of the total score formula.
* **Given**:
  * Section A (Weight = 60.0), triggers a CCP failure. Section earned is zeroed.
  * Section B (Weight = 40.0), earns 5.0 out of 10.0 max points.
* **When**: ScoringEngine.calculate() is run.
* **Then**:
  * The final total score must be exactly `20.0%` (i.e. `((0.0 * 60) + (5/10 * 40)) / (60 + 40) * 100`).

### TC-04: Risk Failure — Answer risk or global risk forces final score to 0
* **Description**: Verifies that if any risk criteria fails, the entire submission is immediately forced to 0.0% total score and marked with `hasRiskFailure: true`.
* **Given**:
  * Section A (Weight = 60.0), triggers a Risk failure.
* **When**: ScoringEngine.calculate() is run.
* **Then**:
  * The final total score must be `0.0%`.
  * `hasRiskFailure` must be `true`.

### TC-05: Zero Section Weights — Falls back to unweighted calculation
* **Description**: Verifies the fallback behavior when the total of all section weights is zero.
* **Given**:
  * Section A (Weight = 0.0), earns 8.0 out of 10.0 max points.
  * Section B (Weight = 0.0), earns 5.0 out of 10.0 max points.
* **When**: ScoringEngine.calculate() is run.
* **Then**:
  * The calculator must fall back to unweighted accumulation, yielding `65.0%` (i.e. `(8.0 + 5.0) / (10.0 + 10.0) * 100`).

### TC-06: ScoringInputMapper — Maps scoreDirection: up and isWeighted: true successfully
* **Description**: Verifies that `ScoringInputMapper.fromTemplate()` correctly parses `scoringLogicConfig` JSON containing `{"scoreDirection":"up","isWeighted":true}` and propagates `isWeighted = true` and `scoringMode = ScoringMode.accumulation`.
* **Then**:
  * `input.scoringMode` is `ScoringMode.accumulation`.
  * `input.isWeighted` is `true`.

### TC-07: Backward Compat — Old template with scoreDirection: up defaults isWeighted to false
* **Description**: Verifies that old templates without the `isWeighted` configuration key are mapped safely to unweighted accumulation (defaulting `isWeighted = false`).
* **Then**:
  * `input.scoringMode` is `ScoringMode.accumulation`.
  * `input.isWeighted` is `false`.
