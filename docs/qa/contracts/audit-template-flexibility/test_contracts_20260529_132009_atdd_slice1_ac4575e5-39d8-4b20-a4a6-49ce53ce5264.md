## 1. Acceptance Criteria (Gherkin Format)

### Scenario 1: Empty Structure Check (Blocking Rule)
*   **Given** an admin user
*   **When** they save a template tree containing zero groups
*   **Then** the server must reject the save with HTTP 422 Unprocessable Entity
*   **And** the response must return a lint result error for `EmptyStructureCheck`

### Scenario 2: Empty Section Name (Blocking Rule)
*   **Given** an admin user
*   **When** they save a template tree containing a group with a blank or null title
*   **Then** the server must reject the save with HTTP 422 Unprocessable Entity
*   **And** the response must return a lint result error for `EmptySectionName`

### Scenario 3: Penalty Mode Group Sum (Blocking Rule)
*   **Given** an admin user
*   **When** they save a template tree with penalty scoring mode where group weights sum to 95% (not 100%)
*   **Then** the server must reject the save with HTTP 422 Unprocessable Entity
*   **And** the response must return a lint result error for `PenaltyModeGroupSum`

### Scenario 4: Duplicate ID Key Collision Check (Blocking Rule - SRE Flop #1)
*   **Given** an admin user
*   **When** they save a template tree with two groups or criteria sharing the exact same Guid ID
*   **Then** the server must reject the save with HTTP 422 Unprocessable Entity
*   **And** the response must return a lint result error for `DuplicateIdCheck`

### Scenario 5: Max Nesting Depth Exceeded Check (Blocking Rule - SRE Flop #2)
*   **Given** an admin user
*   **When** they save a template tree with groups nested 3 levels deep (Group -> Subsection -> Subsubsection)
*   **Then** the server must reject the save with HTTP 422 Unprocessable Entity
*   **And** the response must return a lint result error for `MaxNestingDepthExceeded`

### Scenario 6: Poison Pill Payload Size Limit (Blocking Rule - Audit Risk #2)
*   **Given** an admin user
*   **When** they save a template tree with more than 500 total criteria/groups
*   **Then** the server must reject the save with HTTP 400 Bad Request
*   **And** the response must return a clear size overflow error message

### Scenario 7: IDOR Tenant Ownership Authorization (Blocking Rule - Audit Risk #3)
*   **Given** an admin user belonging to Tenant A
*   **When** they attempt to save a template tree for a template ID owned by Tenant B
*   **Then** the server must reject the request with HTTP 403 Forbidden or HTTP 404 Not Found

### Scenario 8: Progressive Repeat Penalty Overflow Safety (SRE Flop #3)
*   **Given** a criterion with repeated faults under progressive penalty mode
*   **When** the repeated faults count is very high (e.g. 50,000)
*   **Then** the scoring deduction calculation must execute safely without throwing or suffering 32-bit signed integer overflow (no negative deductions)

### Scenario 9: Mixed Audit Scored and Unscored Criteria (Advisory Rule)
*   **Given** an admin user
*   **When** they save a template tree containing a pass_fail scored criterion alongside an unscored text/survey criterion
*   **Then** the server must save successfully with HTTP 200 OK
*   **And** the response must include a lint result warning for `MixedAuditWarning`

### Scenario 10: Silent Risk In Survey Template (Advisory Rule)
*   **Given** an admin user
*   **When** they save a survey template containing a criterion with `isRisk = true`
*   **Then** the server must save successfully with HTTP 200 OK
*   **And** the response must include a lint result warning for `SilentRiskInSurvey`

### Scenario 11: Progressive Zero Impact (Advisory Rule)
*   **Given** an admin user
*   **When** they save a template tree with progressive repeat penalty enabled but the criteria have a `minusImpact = 0` (or null/0 weight)
*   **Then** the server must save successfully with HTTP 200 OK
*   **And** the response must include a lint result warning for `ProgressiveZeroImpact`

### Scenario 12: Existing Valid Template Saves Successfully
*   **Given** an admin user
*   **When** they save a fully valid template tree with no errors or warnings
*   **Then** the server must save successfully with HTTP 200 OK
*   **And** the response must include a lint result with empty errors and warnings
