## 1. Acceptance Criteria (Strict Gherkin Format)

### Feature: Store BOD Summary Endpoint (`GET /api/analytics/stores/{storeId}/bod-summary`)

#### Scenario S1-1: Successful store BOD summary fetch
- **Given** an authenticated user with `AnalyticsBod` capability and a store with 7 completed audits and section scores
- **When** the user requests the store BOD summary endpoint for this store
- **Then** the response status should be `200 OK`
- **And** the response payload should contain `storeName`
- **And** the `recentAudits` list must contain exactly the 5 most recently completed audits, ordered by date descending
- **And** the `categoryBreakdown` list must contain the section scores grouped by `SectionTitle` with correct computed average scores (`Sum(Score) / Sum(MaxScore) * 100`)

#### Scenario S1-2: Store with zero completed audits
- **Given** an authenticated user with `AnalyticsBod` capability and a store with 0 completed audits
- **When** the user requests the store BOD summary endpoint for this store
- **Then** the response status should be `200 OK`
- **And** the `recentAudits` list should be empty
- **And** the `categoryBreakdown` list should be empty

#### Scenario S1-3: Store BOD summary without capability
- **Given** an authenticated user without `AnalyticsBod` capability (e.g., standard auditor role)
- **When** the user requests the store BOD summary endpoint
- **Then** the response status should be `403 Forbidden`

#### Scenario S1-4: Non-existent store (Gap Analysis AC #1)
- **Given** an authenticated user with `AnalyticsBod` capability
- **When** the user requests the store BOD summary endpoint for a random GUID that does not exist in the database
- **Then** the response status should be `404 NotFound`

### Feature: Category Detail Endpoint (`GET /api/analytics/bod/category/{name}`)

#### Scenario S1-5: Successful category detail fetch
- **Given** an authenticated user with `AnalyticsBod` capability and completed submission scores across multiple stores
- **When** the user requests the category detail endpoint for a valid compliance category
- **Then** the response status should be `200 OK`
- **And** the response payload should be a list of `CategoryStoreEntry` objects
- **And** the entries must be sorted by `AvgScore` ascending (worst-performing stores first)
- **And** the list must be capped at 50 records
- **And** the `failureCount` per store must correspond to the number of scores in that section where `IsCcpFailed == true`

#### Scenario S1-6: Category with no score records
- **Given** an authenticated user with `AnalyticsBod` capability and no submission scores matching the requested category name
- **When** the user requests the category detail endpoint
- **Then** the response status should be `200 OK`
- **And** the response payload should be an empty list `[]`

#### Scenario S1-7: Category detail without capability
- **Given** an authenticated user without `AnalyticsBod` capability
- **When** the user requests the category detail endpoint
- **Then** the response status should be `403 Forbidden`

#### Scenario S1-8: Invalid category name (Gap Analysis AC #2)
- **Given** an authenticated user with `AnalyticsBod` capability
- **When** the user requests the category detail endpoint with an empty or whitespace string for the category name (e.g. `GET /api/analytics/bod/category/%20%20%20`)
- **Then** the response status should be `400 BadRequest`
