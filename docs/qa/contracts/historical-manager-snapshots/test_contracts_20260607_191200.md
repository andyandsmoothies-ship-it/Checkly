## Acceptance Scenarios (Gherkin Format)

### Scenario 1: Happy Path — AM and SM snapshot written at finalization (TC-1)
* **Given** an Area Manager profile `AM-1` is assigned to Store `S-1`
* **And** a Store Manager profile `SM-1` is assigned to Store `S-1`
* **And** a draft submission `Sub-1` exists for Store `S-1`
* **When** a request is made to finalize `Sub-1`
* **Then** the `Submission` row in the database has `AreaManagerId` equal to `AM-1.Id`, `AreaManagerName` equal to `AM-1.FullName`, `StoreManagerId` equal to `SM-1.Id`, and `StoreManagerName` equal to `SM-1.FullName`

### Scenario 2: Graceful null — no AM assigned (TC-3)
* **Given** a Store Manager profile `SM-1` is assigned to Store `S-1`
* **And** no Area Manager profile is assigned to Store `S-1`
* **And** a draft submission `Sub-1` exists for Store `S-1`
* **When** a request is made to finalize `Sub-1`
* **Then** the submission is finalized successfully
* **And** the `Submission` row in the database has `AreaManagerId` and `AreaManagerName` set to `null`

### Scenario 3: ActionPlan propagation — AM name flows to action plan (TC-4)
* **Given** an Area Manager profile `AM-1` is assigned to Store `S-1`
* **And** a draft submission `Sub-1` exists for Store `S-1` with a failing answer that triggers an action plan
* **When** a request is made to finalize `Sub-1`
* **Then** the generated `ActionPlan` row in the database has `AreaManagerId` equal to `AM-1.Id` and `AreaManagerName` equal to `AM-1.FullName`

### Scenario 4: Deleted Profile Guard (AC-Gap-1)
* **Given** an Area Manager profile `AM-1` was assigned to Store `S-1` but is subsequently deleted from the database
* **And** a draft submission `Sub-1` exists for Store `S-1`
* **When** a request is made to finalize `Sub-1`
* **Then** the submission is finalized successfully
* **And** the `Submission` row in the database has `AreaManagerId` and `AreaManagerName` set to `null`

### Scenario 5: Idempotency Guard (AC-Gap-2)
* **Given** a completed submission `Sub-1` exists in the database
* **When** a request is made to finalize `Sub-1`
* **Then** the server returns a Conflict response
* **And** the database row is not updated or corrupted
