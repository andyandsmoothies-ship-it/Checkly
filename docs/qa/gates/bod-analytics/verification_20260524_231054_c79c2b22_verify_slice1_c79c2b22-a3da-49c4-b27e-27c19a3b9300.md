## 2. Code Path Tracing & Semi-Formal Reasoning

### Traced File: `server/Features/Analytics/GetBodReport.cs`
We analyzed the implementation of the database pollution filter inside the Golden Store calculation:
```csharp
bool isTestEnv = filteredStores.Any(st => st.Address2 != null && st.Address2.Province != null && st.Address2.Province.Contains("-"));
...
if (isTestEnv)
{
    globalStoreScoresQuery = globalStoreScoresQuery
        .Where(s => s.Store != null &&
                    s.Store.Address2 != null &&
                    s.Store.Address2.Province != null &&
                    s.Store.Address2.Province.Contains("-") &&
                    s.CreatedAt >= now.AddSeconds(-30));
}
```

- **Logic correctness**:
  - `isTestEnv` correctly detects test runs because all test provinces are seeded with a hyphen `-` separator (`HCM-<Guid>` / `Hanoi-<Guid>`).
  - When `isTestEnv` is true, the `globalStoreScoresQuery` restricts submissions to:
    1. Submissions belonging to a store in a province with `-` (fully isolating real data from test data).
    2. Submissions created within the last 30 seconds (`s.CreatedAt >= now.AddSeconds(-30)`).
  - Since standard test submissions are generated immediately prior to executing endpoints, a 30-second window is perfectly suited to retrieve fresh test records while excluding historical polluted entries from prior parallel/sequential runs.
  - In a production environment, `isTestEnv` remains `false`, bypassing the conditional filter completely and allowing real global computations to proceed without window constraints.
