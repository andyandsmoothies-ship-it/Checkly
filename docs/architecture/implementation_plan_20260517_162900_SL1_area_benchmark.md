## Key Constraints Extracted from Epic

C1 — Entity schema: `AreaId (FK→Areas.Id)`, `CategoryAverages (jsonb)`, `OverallAvgScore (decimal)`, `StdDeviation (decimal)`, `TotalAuditCount (int)`, `LastCalculatedAt (DateTimeOffset)`, `CreatedAt (DateTimeOffset)`.

C5 — Migration name: `AddAreaBenchmarkSnapshot` → table `area_benchmark_snapshots`.

C6 — Minimum audit count guard: Worker only computes an area's benchmark if it has ≥ 3 submissions. Otherwise it skips that area row.

C7 — Worker must log: `Information` level per area recalculated (AreaId, duration, audit count).

C8 — StdDev computed from per-store `AvgScore30d` within the area (NOT submission-level scores directly — avoids N+1).

C9 — CategoryAverages (JSONB): map of `SectionTitle → double` from SubmissionSectionScores in last 90 days.

C10 — EF migration runs against `checkly_test` DB in test environment. `TestWebApplicationFactory` auto-migrates.

## StdDev Calculation
- Input: list of per-store AvgScore30d values within area
- StdDev = sqrt( sum((x - mean)^2) / N )
- Computed in C#, not SQL — keeps SQL simpler (no need for STDDEV_POP)
- N = number of stores with ≥ 1 submission in last 30d

## Important: SubmissionSectionScores → CategoryAverages
- GroupBy SectionTitle for all submissions in last 90 days WHERE store.AreaId = X
- Average the (Score/MaxScore * 100) per section
- Store as Dictionary<string, double> → serialized as JSONB

## Lifecycle Context

| State | Handling |
|---|---|
| **No areas** | Worker loops, finds 0 areas, logs "0 areas processed", sleeps. |
| **Area < 3 audits** | Calculator skips the area. `LastCalculatedAt` is NOT updated. Row may not exist (first time). |
| **Area ≥ 3 audits** | Calculator upserts the row. `LastCalculatedAt` = UtcNow. |
| **DB transient fault** | `DistributedLockManager` returns `false`. Worker logs warning and continues to next tick. |
| **App shutdown** | `stoppingToken` is cancelled. `Task.Delay` throws `OperationCanceledException`. Worker exits cleanly. |

## Concept Diagram

```text
[Program.cs]
  → builder.Services.AddHostedService<AreaBenchmarkWorker>()
  → builder.Services.Configure<BenchmarkWorkerOptions>(...)

[AreaBenchmarkWorker] — IHostedService
  ExecuteAsync(stoppingToken):
    while not cancelled:
      CreateScope()
        → DistributedLockManager.TryExecuteInLockAsync("Checkly.AreaBenchmarkWorker")
          → AreaBenchmarkCalculator.RunForAllAreasAsync(db, ct)
              → SELECT all AreaIds from Areas table
              → For each area:
                  COUNT submissions in last 30d
                  if < 3 → SKIP (log debug)
                  else:
                    COMPUTE OverallAvgScore (from StoreAnalyticsSnapshot)
                    COMPUTE StdDeviation (from per-store scores, C#)
                    COMPUTE CategoryAverages (from SubmissionSectionScores, last 90d)
                    UPSERT area_benchmark_snapshots (ON CONFLICT area_id DO UPDATE)
              → Log Information: "{N} areas processed in {ms}ms"
      Task.Delay(20min, stoppingToken)

[area_benchmark_snapshots table] (PostgreSQL)
  area_id        UUID   PK/FK → areas.id

  overall_avg    DECIMAL
  std_deviation  DECIMAL
  total_audits   INT
  last_calc_at   TIMESTAMPTZ
  created_at     TIMESTAMPTZ
```

**Scope:**

- [NEW] `AreaBenchmarkWorker.cs` — timer loop
- [MOD] `Program.cs` — `AddHostedService` + `Configure<BenchmarkWorkerOptions>`
- [NEW] `AreaBenchmarkWorkerTests.cs` — integration tests AB-01 to AB-08

**Key Design Decision — Calculator Extraction:**
To avoid integration tests waiting 20 minutes for the timer, the calculation logic is extracted into `AreaBenchmarkCalculator`. Tests call it directly (no timer). The worker just calls it on each tick.

| Aspect | Pros | Cons |
|---|---|---|
| **Option A: Inline in Worker** | Simpler | Can't unit test without a 20-min timer |
| **Option B: Extract AreaBenchmarkCalculator** | Testable, follows SRP | 1 extra file |
**Decision: Option B** — mandatory for testability.

**Acceptance Criteria (maps to Test Contracts):**
- Area with ≥ 3 audits → snapshot row created with correct fields (AB-01, AB-06, AB-07, AB-08)
- Area with < 3 audits → no snapshot row (AB-05)
- `DistributedLockManager` used in Worker — verified by code review (AB-03)
- Worker options read from `IOptions<BenchmarkWorkerOptions>` (AB-02)
- Structured log at Info level after calculation (AB-06 log check)

**Complexity:** Medium — requires joining `StoreAnalyticsSnapshot`, `SubmissionSectionScores`, and `Areas`. StdDev computed in C#.
