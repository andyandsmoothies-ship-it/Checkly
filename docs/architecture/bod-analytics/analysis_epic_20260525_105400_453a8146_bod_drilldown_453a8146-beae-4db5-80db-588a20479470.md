## Architecture Decision

Pattern: Modal Overlay Drill-Down (lazy-load on sheet open). Not a navigation pattern.
Reason: GoRouter ShellRoute issues (Gotcha 15). BOD presentation context — admin must not lose filtered state.

The 4 distinct drill-down types:
1. AP Bucket → already has modal, needs client bridge fix
2. Store → replace sync modal with real summary
3. Category → new endpoint + new sheet
4. Auditor → new sheet calling LIVE auditor endpoint (not snapshot, BiasRating gap)

Key discovery: Category weakness data flows through `SubmissionSectionScores` table (has `SectionTitle`, `StoreId`, `Score`, `MaxScore`). This table IS registered in `AppDbContext` as `SubmissionSectionScores`. The `GetCategoryDetail` handler can query this table + read `StoreName` from the denormalized `Submission.StoreName` field via navigation. No need to JOIN `Stores` table.

Critical risks:
1. `GetCategoryDetail` may be slow without index on `SubmissionSectionScore.SectionTitle`. Must add `.Take(50)` + `AsNoTracking` + IMemoryCache.
2. Snapshot vs Live mismatch: main dashboard is from nightly snapshot; drill-downs are LIVE. Must show "Live data as of [now]" note.
3. `BodReportCalculator.cs` is 419 lines — OUT OF SCOPE. No modifications.
4. The `GetApBucketDetail.cs` uses bucket names `0-30d`, `31-60d`, `61-90d`, `90d+`. But the Flutter `BodApAgingFunnel` passes bucket names like `0-30 Days`, `31-60 Days`, etc. The builder must normalize this mapping.

Slim choice: Option B (Pragmatic Balance). 4 slices. 2 new server handlers. 2 new Flutter sheets. Fix 2 client wiring gaps.
