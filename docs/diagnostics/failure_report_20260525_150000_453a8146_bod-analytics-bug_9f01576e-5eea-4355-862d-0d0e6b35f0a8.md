# Failure Report: Flutter markNeedsBuild setState Called During Build in BOD Analytics Sheets

## Input Lineage
- **Source Input**: c:\Users\HP\Documents\GitHub\Checkly\lib\features\analytics\manager\bod_analytics_manager.dart

## Root Cause
When opening any of the three Boardroom (BOD) Analytics detail sheets (`BodStoreDetailSheet`, `BodCategoryDetailSheet`, or `BodAuditorDetailSheet`), their `initState()` method synchronously calls the manager's state loading method:
- `BodStoreDetailSheet` -> `loadStoreDetail(widget.storeId)`
- `BodCategoryDetailSheet` -> `loadCategoryDetail(widget.categoryName)`
- `BodAuditorDetailSheet` -> `loadAuditorDetail(widget.auditorName)`

Inside each of these load methods in `BodAnalyticsManager`:
1. The manager sets the loading status (e.g. `_isStoreDetailLoading = true`).
2. The manager synchronously calls `notifyListeners()`.

Because the bottom sheet widget is in the middle of being built and mounted (or its parent screen's `ListenableBuilder` or the sheet's `AnimatedBuilder` is actively listening to changes), the synchronous call to `notifyListeners()` immediately schedules a rebuild via `markNeedsBuild()` / `setState()` on the listening builder. This is executed during the build pipeline of the widget tree, which is strictly prohibited by Flutter and causes a `FlutterError`.

## Explicit Code Trace (Premises + Proof)

1. **Premise A**: `BodStoreDetailSheet` mounts inside the `showModalBottomSheet` pipeline.
2. **Premise B**: During mount, `_BodStoreDetailSheetState.initState()` (line 25) executes.
3. **Premise C**: `initState()` calls `widget.manager.loadStoreDetail(widget.storeId)` synchronously.
4. **Premise D**: `BodAnalyticsManager.loadStoreDetail` (line 266) executes:
   ```dart
   Future<void> loadStoreDetail(String storeId) async {
     if (_isStoreDetailLoading) return;
     _isStoreDetailLoading = true;
     _error = null;
     notifyListeners(); // <-- synchronously called during build frame
   ```
5. **Premise E**: `notifyListeners()` instantly notifies all active listeners. The listening `AnimatedBuilder` (line 40) or `ListenableBuilder` (in the parent page) is registered as a listener to the manager.
6. **Proof**: Flutter invokes `markNeedsBuild()` / `setState()` on the active builder. Because the widget tree is in the middle of a build frame (building `NotificationListener<DraggableScrollableNotification>`), the framework throws:
   `FlutterError (setState() or markNeedsBuild() called during build.)`

---

## Proposed Scope-Limited Fix

Wrap the load calls inside the bottom sheets' `initState` methods inside a post-frame callback using `WidgetsBinding.instance.addPostFrameCallback((_) { ... })`. This schedules the execution of the state load and `notifyListeners()` for the next frame, immediately after the current build frame completes successfully.

### Trade-offs / Pros & Cons
- **Pros**:
  - **100% Reliable**: Fully resolves the `markNeedsBuild()` called during build exception.
  - **Standard Pattern**: Perfectly aligns with the existing pattern used in `bod_analytics_page.dart` (line 32) and recommended Flutter practices.
  - **Zero Backend Impact**: Scope-limited entirely to UI initialization without touching any network API or core backend structures.
- **Cons**:
  - The load call is deferred by exactly one frame (negligible delay of <16ms).
