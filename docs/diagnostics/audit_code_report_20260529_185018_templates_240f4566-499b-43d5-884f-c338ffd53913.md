### 🔴 CRITICAL — C1: Inline Hardcoded Mock Data in Production Service

| Field | Value |
|---|---|
| **File** | `lib/features/analytics/services/bod_analytics_api_service.dart` |
| **Lines** | 20–147, 191–291, 302–327, 341–361, 371–386 |
| **Rule** | Architecture Drift — Business data inside the service layer |

**Problem**: All 5 public methods in `BodAnalyticsApiService` contain large inline mock data (>200 lines total) embedded directly inside `catch` blocks as `fromJson({...})` calls. This is a dual violation:
1. **Business data lives inside infrastructure** — mock store names, IDs, scores are hardcoded inside the HTTP service class.
2. **Silent failure masking** — every network failure silently returns fake success data. This means production backend failures are completely invisible to operators and the developer.

**Flow**:
```
API call fails → catch block → returns mock JSON → UI shows "real" data
                                                  → operator sees green dashboard
                                                  → backend is actually down ❌
```

**Fix**: Extract fallback data to a dedicated `BodMockData` class in `lib/features/analytics/services/mock/`. The service should re-throw or return a typed failure result (`Result<BodReportResponse, AppError>`). Only inject mock data in dev builds.

```dart
// BEFORE (in service catch block):
} catch (e) {
  debugPrint('[BOD] ...');
  return BodReportResponse.fromJson({ "kpis": { ... 50 lines ... }});
}

// AFTER (service):
} catch (e, s) {
  if (kDebugMode) return BodMockData.defaultReport();
  throw AppError.network(e.toString());
}

// NEW: lib/features/analytics/services/mock/bod_mock_data.dart
class BodMockData {
  static BodReportResponse defaultReport() => BodReportResponse.fromJson({...});
}
```

**Complexity**: **High** — Requires creating a `Result` type or error propagation contract. All calling widgets in `BodAnalyticsManager` must handle the failure path explicitly. Ripples to `bod_analytics_page.dart`.

**Trade-offs**:
- ✅ **Pro**: Makes backend failures visible. Prevents silent data lies to operators.
- ✅ **Pro**: Shrinks `bod_analytics_api_service.dart` from 389 lines to ~90 lines.
- ⚠️ **Con**: Requires all consumer widgets to handle the error state, which is currently implicit. Adds a short-term refactor burden.

### 🟡 WARNING — W4: `dynamic auditorDetail` Weak Type in Manager

| Field | Value |
|---|---|
| **File** | `lib/features/analytics/manager/bod_analytics_manager.dart` L30, 54 |
| **Rule** | Use Strong Types |

**Problem**:
```dart
dynamic _auditorDetail;
dynamic get auditorDetail => _auditorDetail;
```
`auditorDetail` is typed as `dynamic` because `getAuditorProductivity()` returns `List<dynamic>`. Any consumer must cast and null-check manually with no compile-time safety.

**Fix**: Promote `_auditorDetail` to the typed `Map<String, dynamic>?` — or better, create a `BodAuditorEntry` value class if it doesn't exist yet in `bod_analytics_data.dart`. The `getAuditorProductivity()` return type in the service should be `List<BodAuditorEntry>`.

**Complexity**: **Low** — Localized to two files. The data shape is already documented in the mock data.

**Trade-offs**:
- ✅ **Pro**: Full compile-time safety and IDE autocomplete for consumers.
- ⚠️ **Con**: Requires a minor refactor to `getAuditorProductivity()` return type.

### 🟡 WARNING — W5: Bucket Name Normalization Logic is a Magic String Tangle

| Field | Value |
|---|---|
| **File** | `lib/features/analytics/manager/bod_analytics_manager.dart` L244-261 |
| **Rule** | No Magic Strings |

**Problem**: `loadApDetails()` contains 8 `trimmed.contains(...)` string comparisons against hardcoded bucket name fragments (`'0-7'`, `'8-30'`, `'31-90'`, etc.). This is brittle — a label change in the UI breaks the API call silently.

**Fix**: Define an `enum BodAgingBucket { sevenDays, thirtyDays, ninetyDays, overdue }` with a `toApiKey()` method. The UI passes the enum, not raw strings.

**Complexity**: **Low** — Enum is self-contained. Requires updating the call sites in `bod_dashboard_body.dart`.

**Trade-offs**:
- ✅ **Pro**: Compile-time safety against label drift.
- ✅ **Pro**: Eliminates 8 magic string comparisons.
- ⚠️ **Con**: Small churn at call sites.
