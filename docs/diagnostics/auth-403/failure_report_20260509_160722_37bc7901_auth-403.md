# Failure Report: AM User 403 on /api/programs/assignments/my

## Input Lineage
- **Source Input**: User chat log — terminal output showing `[16:01:58 INF] HTTP GET /api/programs/assignments/my responded 403 in 1.4155 ms`
- **Symptom**: `area_manager` user receives `403 Forbidden` when the Flutter app syncs program assignments on login or dashboard load.

---

## Root Cause

The `area_manager` role is absent from the PBAC capability seed for `programs:assignments_my` and `programs:execute`. The Flutter `SyncEngine` registers `ProgramSyncModule` for **all** authenticated roles without a role gate. On every sync cycle, `ProgramSyncModule.executePull()` fires `GET /api/programs/assignments/my` — a route guarded by `.RequireCapability(AppCapabilities.ProgramsAssignmentsMy)`. Because the PBAC cache contains no row mapping `(area_manager, programs:assignments_my)`, the middleware fails-closed and returns 403.

**This is a violation of the "7 Sync Steps" gotcha** from `GEMINI.md`: *"If adding a capability, seed it in `Program.cs` AND `TestWebApplicationFactory.cs`."* When Slice 2A extended programs access to `store_manager`, no equivalent extension was seeded for `area_manager`.

---

```
            → FALSE (row does not exist in role_capabilities table)

```

**Write-Path Origin** — `Program.cs` lines 348–355:
```csharp
// Programs Module Slice 2A / PBAC execution
await db.Database.ExecuteSqlRawAsync("""
    INSERT INTO role_capabilities (id, role, capability, created_at)
    VALUES
        (gen_random_uuid(), 'store_manager', 'programs:assignments_my', now()),
        (gen_random_uuid(), 'store_manager', 'programs:execute', now())
    ON CONFLICT (role, capability) DO NOTHING;
    """);
```
`area_manager` is entirely absent from this block.

**Mirror gap** — `TestWebApplicationFactory.cs` lines 135–136:
```csharp

```
Same missing rows in the test seed.

**Handler is already AM-compatible** — `GetMyAssignments.cs` scopes by `profile.StoreId`, which is populated for AM users via `ProfileStoreAssignment`. No handler changes are needed.

## Proposed Scope-Limited Fix

**Two file changes. Zero business logic changes.**

### Fix 1 — `server/Program.cs` (lines 348–355)
Add `area_manager` rows inside the existing Slice 2A INSERT:

```csharp
// Programs Module Slice 2A / PBAC execution: Seed store_manager + area_manager (idempotent)
await db.Database.ExecuteSqlRawAsync("""
    INSERT INTO role_capabilities (id, role, capability, created_at)
    VALUES
        (gen_random_uuid(), 'store_manager', 'programs:assignments_my', now()),
        (gen_random_uuid(), 'store_manager', 'programs:execute',        now()),
        (gen_random_uuid(), 'area_manager',  'programs:assignments_my', now()),
        (gen_random_uuid(), 'area_manager',  'programs:execute',        now())
    ON CONFLICT (role, capability) DO NOTHING;
    """);
```

### Fix 2 — `server/tests/Checkly.Api.Tests/TestWebApplicationFactory.cs` (lines 135–136)
Mirror the same rows in the test factory SQL block:
```csharp
(gen_random_uuid(), 'store_manager', 'programs:assignments_my',     now()),
(gen_random_uuid(), 'store_manager', 'programs:execute',            now()),
(gen_random_uuid(), 'area_manager',  'programs:assignments_my',     now()),
(gen_random_uuid(), 'area_manager',  'programs:execute',            now())
```

### Trade-offs / Pros & Cons

| | Detail |
|---|---|
| **Pro** | Fixes the 403 without any Flutter or handler code changes — lowest blast radius possible. |
| **Pro** | `ON CONFLICT DO NOTHING` makes the seed fully idempotent — safe to apply to existing running DB. |
| **Pro** | Aligns with the system architecture: AM users ARE assigned to stores and should be able to view/execute programs assigned to those stores. |
| **Con** | AM users will now see and be able to submit program assignments. Verify that the Flutter Programs UI correctly displays assignments for AM users (e.g., `ProgramsPage` is visible in their nav). |
| **Con** | `SubmitProgramEvidence.cs` docstring says *"restricted to role=store_manager"* — this comment is now stale. **Update the comment** when implementing. |
| **Edge Case** | If an AM is assigned to multiple stores (via `ProfileStoreAssignment`), `GetMyAssignments` will only return assignments for `profile.StoreId` (the primary store). This is a pre-existing limitation, not introduced by this fix. |

**Executive Decision Required**: Confirm that Area Managers should have full program execution access (view + submit evidence) before Builder implements.
