# Diagnostic Report: Npgsql DateTimeOffset Exception

## Input Lineage
- **Source Input**: `GET /api/analytics` user logs showing HTTP 500
- **Log Snippet**: `System.ArgumentException: Cannot write DateTimeOffset with Offset=07:00:00 to PostgreSQL type 'timestamp with time zone', only offset 0 (UTC) is supported.`

## Root Cause
Npgsql enforces strict UTC mappings for the `timestamp with time zone` (timestamptz) PostgreSQL column type. When the Flutter frontend sends a date filter string with a local timezone offset (e.g., `+07:00`), `DateTimeOffset.TryParse` parses it successfully and preserves that non-zero offset. However, EF Core passes this parameter unchanged into the Npgsql provider, which explicitly throws an exception if the `Offset` property is anything other than `0` (UTC).

## Explicit Code Trace (Premises + Proof)
1. In `GetAnalytics.cs` (lines 27-30), the API reads `startDate` and `endDate` from the query string using `DateTimeOffset.TryParse(..., out var parsedStart)`.
2. The `startDateFilter` variable is assigned the raw parsed value, which retains the local timezone offset sent by the client.
3. At line 141, the query applies the filter: `query.Where(s => s.CreatedAt >= startDateFilter.Value)`.
4. EF Core executes the query. Npgsql attempts to bind the `DateTimeOffset` parameter but faults because the offset is `07:00:00` instead of `00:00:00`.
*Note: A secondary audit using `grep_search` found the exact same vulnerability in `ListSystemLogs.cs`.*

## Proposed Scope-Limited Fix
We need to normalize the parsed `DateTimeOffset` values to UTC before passing them to the EF Core query engine. 

**Fix:** Append `.ToUniversalTime()` to the `TryParse` outputs.

**Trade-offs / Pros & Cons:**
- **Pros:** Completely resolves the Npgsql exception without changing the semantic time bounds. It is a 0-impact change to the database and correctly aligns the client's local time request with the server's UTC-stored records.
- **Cons:** It requires a manual `.ToUniversalTime()` call in every endpoint that manually parses query dates. This relies on developer discipline.
