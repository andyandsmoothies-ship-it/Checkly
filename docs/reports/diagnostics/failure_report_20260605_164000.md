# Failure Report: Store Saving Hang After Location Update

## Input Lineage

- **Source Input**: `lib/features/admin/pages/widgets/store_form_save_logic.dart`

## Root Cause

1. **Missing State Mutation (isSaving)**: On successful store creation or update, the `isSaving` flag is never set back to `false`. This causes the save button's progress indicator to animate indefinitely.
2. **Missing Rebuild for Navigation Guard (isDirty)**: On success, the `isDirty` flag is set to `false` directly without wrapping it in a `setState` call. Because the widget does not rebuild, the `UnsavedChangesGuard` wrapped around the sheet retains its stale `isDirty = true` configuration. When `Navigator.maybePop(context)` is called, the `PopScope` intercepts it, blocks the pop, and displays the "Discard changes?" confirmation dialog while the spinner continues to run.

## Explicit Code Trace

### Premise 1: Initialization of Saving State
In `lib/features/admin/pages/widgets/store_form_save_logic.dart`, the `saveStore` method begins the save process:
```dart
setState(() => isSaving = true);
```

### Premise 2: Missing Success Recovery
Upon successful completion of the API call, the success branch executes:
```dart
if (mounted) {
  isDirty = false;
  Navigator.maybePop(context);
  // ... snackbar and onSaved()
}
```
*Proof*: No call to `setState` is made to update the widget tree with `isDirty = false`, and `isSaving` is never updated to `false`.

### Premise 3: Pop Scope Interception
In `lib/features/admin/pages/widgets/store_form_sheet.dart`, the build method returns:
```dart
UnsavedChangesGuard(
  isDirty: isDirty,
  child: ...
)
```
Since `setState` was not called, `isDirty` is still seen as `true` by the `UnsavedChangesGuard`, which intercepts the `Navigator.maybePop(context)` call and prompts the user with a confirmation dialog.

---

## First Principles Gate

### 1. Physics & Limit
- **Limit**: UI event loop/state consistency.
- **Source of Truth**: The local reactive widget state (`isSaving`, `isDirty`).

### 2. Simplicity Check
- **Simplest Patch**: Wrap `isDirty = false; isSaving = false;` in `setState(() { ... })` inside the success block before calling `Navigator.maybePop`.
- **Why NOT to do it differently**: Refactoring the state architecture is unnecessary since this is a localized state coordination problem.

### 3. Blast Radius
- **Worst Case**: The form sheet dismisses successfully but leaves the list in a dirty or stale state. Safe scope (restricted to the Store Management Page's form modal).

### 4. Observability
- **Production Proof**: Successful response from PUT/POST followed by the sheet closing. Verification through automated widget test checking that the sheet is dismissed after saving.

---

## Proposed Scope-Limited Fix

```diff
-      if (mounted) {
-        isDirty = false;
-        Navigator.maybePop(context);
+      if (mounted) {
+        setState(() {
+          isDirty = false;
+          isSaving = false;
+        });
+        Navigator.maybePop(context);
```

### Pros & Cons / Trade-offs:
- **Pros**: Zero dependencies, minimal blast radius, immediately resolves the hang and prevents the "Discard changes?" dialog from appearing on successful save.
- **Cons**: None identified.
